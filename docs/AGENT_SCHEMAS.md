# Agent schemas and validation

`flowx_os.agents.schemas` defines strict, frozen, provider-neutral data contracts for agent requests and evidence-backed research, strategy candidates, script drafts, and storyboard drafts. Agent roles are an allowlist. Requests pin prompt and policy versions and bound caller input to 32 KiB of JSON-compatible values. Output fields have explicit size/count/range limits; unknown fields are rejected. Evidence references require an HTTP(S) URL with a valid port and a publicly routable literal host, plus an excerpt. Storyboard scene numbering must be sequential.

Model-provider responses and user-authored data are untrusted input. Parse request envelopes with `validate_agent_request` and outputs with `validate_agent_output(schema, data)`. These return typed models or `AgentSchemaError`, which exposes bounded schema paths (unknown keys are represented generically) and Pydantic error codes, not rejected values. Avoid logging raw payloads. These schemas never fetch citation URLs. Any future retrieval component must resolve hosts safely, deny private/reserved destinations after resolution, and enforce network egress restrictions to prevent SSRF and DNS rebinding. Output models reject malformed data but do not establish factual accuracy, rights, policy compliance, user approval, or permission to publish. Downstream review and approval gates remain authoritative.

These are data contracts only. No model SDK, provider credentials, agent executor, persistence, or external verification is included. Unit tests validate schema behavior and error redaction; live provider behavior is not claimed.
