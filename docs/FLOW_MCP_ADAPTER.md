# Flow MCP adapter boundary

`CapabilityGatedFlowAdapter` is the app-side safety boundary for a future Flow MCP transport. It is deliberately not wired to the Codex desktop tool catalog: the host exposes Flow MCP tools to this session, but the repository has no verified transport endpoint or deployment identity. A `ManifestProvider` and `McpTransport` must be supplied by a separately authorized runtime integration.

The adapter is disabled by default. When enabled, it requires an expected server ID and opaque local account reference, a verified account authorization, a fresh manifest (15 minutes by default), an explicit normalized-operation binding to a tool present in that manifest, and arguments satisfying the supported discovered JSON Schema subset. Schemas are copied and recursively frozen; unsupported keywords, malformed constraints, or invalid argument values fail closed. Video generation or any other spending binding additionally requires an approval reference scoped to the same account and operation with a positive maximum credit ceiling, plus an injected trusted `SpendAuthorizationVerifier`. No email, cookies, access tokens, or credentials belong in these objects.

Failures use stable `FlowAdapterError` codes and sanitized messages. Raw MCP exceptions and remote result data are untrusted. The adapter only verifies that a result is a mapping; callers must validate operation-specific fields, file paths, media bytes, job state, idempotency, and credit reconciliation before using them. The trusted verifier proves that the human approval reference and ceiling are valid; until a verified quote or conservative cost table exists, this boundary cannot prove actual spend stays below that ceiling and must not be used to authorize unattended paid generation.

No live transport is configured, no Flow operation was invoked, no generation was submitted, and no production integration is claimed. Current observed capabilities and external prerequisites are tracked in `MCP_CAPABILITY_MATRIX.md`; account verification and old-job reconciliation remain TASK-023 and TASK-024.
