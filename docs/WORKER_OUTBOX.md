# Transactional outbox and worker leases

Use `enqueue_job` inside `unit_of_work` with the domain write that creates the work item. Its caller-supplied UUID idempotency key is unique in the database; replays return the existing job ID. The key must remain stable for the same logical operation.

Run `lease_due_jobs` inside a short unit of work. It uses `FOR UPDATE SKIP LOCKED`, accepts due ready rows or expired leases, applies bounded lease duration and batch limits, increments attempts, and returns lease ownership. Workers should commit the lease before doing remote or long-running work. `complete_job` only succeeds for the current lease owner and clears lease fields.

Migration `0002_outbox_idempotency.sql` adds the key and indexes. Apply migrations in order. `record_job_failure` releases a failed current lease and either schedules a bounded retry or moves an exhausted/non-retryable attempt to `DEAD`, storing only a safe error code. `list_dead_jobs` returns bounded metadata without payloads; `requeue_dead_job` explicitly resets one dead job for operator replay. A lease heartbeat/extension operation is not implemented, so handlers must remain within the lease duration or stop before lease expiry. These SQL operations have unit coverage, but production worker execution and PostgreSQL concurrency remain unverified; do not deploy workers until those operational guarantees are exercised. Reconcile a lost lease before repeating external side effects.
