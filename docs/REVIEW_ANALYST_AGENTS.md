# Prompt, review and analyst agents

`config/prompt_registry.json` stores multiple versions of local prompt definitions under each prompt ID. Callers can retrieve a pinned version; omitting the version selects the highest registered version. Every definition declares a static system instruction, a user template, and the exact set of allowed string variables. Registry loading rejects unknown fields, unsafe variable names, template expressions/conversions, undeclared or missing placeholders, duplicate prompt ID/version pairs and credential-like static content. Rendering accepts only the exact variable set, bounds each value and the combined prompt, and rejects common credential patterns. Variable values are inserted as data; brace characters inside values are not re-evaluated. Prompt rendering itself does not call a provider. Do not log rendered prompts or pass credentials, raw tokens, or secrets as template values.

`ContentReviewWorkflow` accepts a typed script/storyboard package, prompt/policy versions and bounded source snapshots. It validates input citations, calls only an injected reviewer, validates the structured assessment, and binds every finding's evidence IDs to the original source set. A provider may return `blocked`, `needs_revision`, or `ready_for_human_review`. The workflow always emits `human_approval_required=true`, `approval_state=pending_human` and `content_approved=false`; model output cannot authorize approval, scheduling, publishing, or generation. A ready assessment is only a request for human review, never approval.

`ContentAnalystWorkflow` accepts bounded metric observations with safe identifiers, finite numeric values, timezone-aware timestamps, and unique observation IDs. It validates untrusted analysis output and requires every finding to reference IDs supplied for that analysis. This verifies references only. It does not establish that an observation is authentic, comparable, statistically meaningful, or causal. Human interpretation is always required.

Both provider protocols are interfaces only. They make no SDK, network, model or database calls themselves. Exceptions and malformed provider results become stable payload-free errors. Fake-provider tests verify boundaries and policy; no live model, analytics platform, Flow MCP, paid generation, or publishing integration is configured or claimed.
